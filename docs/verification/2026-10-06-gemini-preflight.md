# Gemini isolated inventory and account setup investigation

Date: 2026-10-06. Scope: M8-T01c, DEC-057/058; developer tooling only. Gemini production generation remains disabled and Claude work remains owner-paused.

## Acceptance and implementation

Inspect the same hash-bound official Gemini CLI 0.62.0 core as the [login checkpoint](2026-10-06-gemini-login-and-claude-pause.md), using native-only credentials in the dedicated qualification service/profile. Normal tests use synthetic JavaScript doubles and do not import the staged provider, read credentials or contact a network.

`qualify_gemini --inventory` creates an explicit Config and tool registry in a disposable workspace, without initializing provider sessions, agents, extensions, tools or authentication. The cached registry is empty. The research registry contains only `google_web_search` and `web_fetch`, in both all-known and model-visible declarations. Eight denied tool categories are checked in each configuration using the actual pinned policy engine: shell, file read/write/edit, skills, agents, MCP and unknown tools. The two permitted research tools receive allow decisions. No model/tool call is made. This proves construction/policy behavior only, not execution isolation, URL safety or model routing.

`--live` reads the existing authenticated account and permits only the initial official account-discovery request and one quota request. It never starts login or onboarding. Fixed destinations/bodies, no retry/redirect, request timeout/response-size limits, known tier/quota fields and fixed failure categories prevent account/project details or raw errors from reaching reports. Quota-associated model IDs are not an entitlement catalog. No generation or API/credit billing is enabled.

`--complete-free-setup` is a separate explicit operation to finish the already authorized Gemini connection. It accepts only the provider's unique default `free-tier`, without a user-defined Cloud project or further account-verification requirement. It performs at most one setup write, then at most six five-second polls of the same validated operation. Existing accounts take a read-only path. Paid/ambiguous/unknown/default-missing tiers, quota/errors, path changes and uncertain results stop without retrying the write. Account metadata must be read again afterward.

## Remaining production gates

Tool-registry isolation does not remove model fallback/routing or qualify search/page-reading. Generation also has provider conversation-metrics paths (especially edit-tool interactions) that need explicit exclusion before enabling a transport. Remaining M8 acceptance includes a supported bounded transport, authoritative model selection/usage enforcement, runtime execution/URL isolation, cancellation/reconnect, application onboarding/model UI, and live source/evidence/freshness checks.
