# Desktop implementation backlog

This tracks actual delivery against [the approved architecture](NEW_STRUCTURE.md) and [product requirements](PRD.md). “Implemented” means the named slice has code and passing checks, not that its entire milestone is complete. Public v1 is **not ready**. No live subscription or clean-machine installer acceptance has been established. This document owns delivery status and dated results; requirements remain the target even where preview behavior is narrower.

## Current state

- Implemented: architecture/product/engineering documentation consolidation; React/Vite entry and npm workspace migration; generated contracts; authenticated API; private PostgreSQL startup/initial migration/shutdown; durable research jobs and cancellation/recovery; atomic publication of immutable evidence snapshots; conservative admission; library, notes, source inspection, saved reports, conversation storage/bookmarks/expiry, explicit cached-asset scope changes and personal exports.
- Tested locally: synthetic research across six asset types, authentication, cache reuse/versioning, cancellation/recovery, safe provider event normalization, frontend rendering/transport, PostgreSQL cluster startup/readiness/clean shutdown, retained financial regression tests and frontend type/build checks.
- Typed searches resolve exact cached symbols, names and qualified identities without inference. Ambiguous cached symbols require selection; stale evidence remains searchable offline with its original dates. Online stale searches retain the resolved identity for refresh. Substring matches and general questions do not silently select an asset.
- Experimental: Codex App Server transport and Claude cached-material transport. They have not passed live compatibility or complete permission-isolation qualification. Gemini safely refuses execution until that qualification exists.
- Codex device-code onboarding is implemented with authenticated start/status/cancel endpoints, in-memory authorization state and a dedicated provider-owned profile. Deterministic lifecycle scenarios and browser initiation/cancellation passed. The installed Codex App Server handshake passed against a fresh unauthenticated profile without login or inference. A successful real subscription authorization is still unverified.
- Native shell source is present but compilation and tray behavior still require a Rust/MSVC build and native UI testing. PyInstaller produced the Windows sidecar with development test packages excluded, and its private PostgreSQL initialization, migrations, authenticated API and clean shutdown passed the packaged smoke test. Installed Postgres 17 binaries were used only to create isolated test clusters; this does not validate bundled PostgreSQL redistribution or a clean-machine installer.
- Portable full-library backup/restore is implemented for current database-held content: authenticated download, preview, strict archive validation, atomic restore into an empty library, credential exclusion and interrupted-job handling. The real PostgreSQL round trip and browser workflow passed. Current archive limits are 128 MiB compressed / 256 MiB content; larger libraries and future attachment formats still require streaming/archive extensions.
- Term learning now supports arbitrary typed or selected terms, cached hover/focus, curated offline definitions, version/language/level-scoped generated explanations, cancellation and citation inspection. Refresh queues previously used terms for the new evidence version while preserving older explanations. Terms are interpretations only, excluded from canonical facts and future factual context. Backup/restore includes terms and validates their references. Deterministic and synthetic-browser checks passed; live explanation quality and provider parity remain unverified.
- Full feature parity, structured financial ingestion, imports, charts/calculations, comparison persistence, source review, complete three-provider onboarding, document-cache retention, coordinated upgrades/rollback and installer acceptance remain open. Settings fields alone do not implement these features.

Current limits that affect use: research streams progress and publishes a whole validated bundle at completion; it does not yet publish sections incrementally. Search uses a simple 24-hour snapshot freshness rule, not per-source refresh policies. Uncached identity/evidence comes from a single structured runtime response; independent identity and financial-source adapters remain open. Only literal prose can enter the initial fact layer, using two initial domain rules. Source rights, numeric/semantic validation and language quality still need broader qualification. Manual review currently prevents automatic admission but offers no review queue. Model selection UI, start-at-login, update execution, document-cache eviction and user deletion controls remain unfinished.
