# Learn the Ticker technical design

[DECISIONS.md](DECISIONS.md) owns architectural decisions; this document defines implementation boundaries. [SPEC.md](SPEC.md) owns behavior. The current implementation is a developer preview, with open release work in [the task queue](TASKS.md).

## Application layout

- apps/desktop/src: Vite entry, route state, authenticated client and generated contract types.
- apps/desktop/components, lib, styles: preserved React components and deterministic reference contracts. Only explicitly imported modules enter the production bundle.
- apps/desktop/src-tauri: native supervisor, private bootstrap IPC, tray and single-instance behavior.
- backend/app: production service contracts, API, persistence, research orchestration, evidence and runtime adapters.
- backend/migrations: explicit Alembic revisions.
- contracts/desktop.schema.json: generated from Pydantic; not edited by hand.
- tests/desktop: synthetic behavior scenarios. Existing backend tests remain migration regression coverage.

The desktop entrypoint does not mount backend/main.py. Its old fixture APIs, coverage gate and mock OpenRouter behavior are isolated from the new production route. Retain those modules only until their useful algorithms and regression scenarios have migrated; do not claim old mock provider implementations are live adapters.

## Contracts and persistence

Pydantic models are the source of truth. Run `.venv/Scripts/python.exe -m scripts.contracts`, then `node scripts/generate_types.mjs`. Requests, admitted runtime output and persisted domain records use these contracts; vendor formats stop at the adapter boundary. The current HTTP client uses generated TypeScript types, which do not themselves provide runtime response validation. Complete typed response coverage remains part of contract hardening.

SQLAlchemy stores versioned records, durable jobs and normalized events. Record kinds distinguish current asset view, immutable evidence bundle, immutable term explanation, conversation, saved report and settings. No application credentials are stored in the database. PostgreSQL is required in production. SQLite is a deterministic unit-test double only; native PostgreSQL smoke tests verify migrations and lifecycle separately.

Current bundle snapshots are immutable. Refresh adds a bundle and updates the current pointer. Reports retain the original bundle ID. Bundle publication, current-page or conversation references, the evidence event and job completion commit in one transaction. A follow-up creates its own cited artifact without replacing the overview. A future migration must add relational constraints/indexes when query scale requires them; JSON documents do not waive schema validation.

Conversation scope changes require a resolved cached identity and are recorded in the transcript. Scope cannot change while its answer is running. Bookmarks prevent expiry. Startup and conversation-list reads expire unbookmarked conversations after their configured inactivity period, including related job requests/events; saved evidence snapshots remain intact. General document-cache retention remains to be implemented.

On startup, pending/running jobs become interrupted rather than replaying subscription calls. Explicit cancellation closes the provider transport. Reconnect reads durable status/events; it never creates another run automatically. The current service shares a 20-job bound and one inference semaphore between research and terms. Two retrieval slots are defined, but source verification currently runs serially inside each research job. A scheduler that exercises two independent retrieval jobs remains target work. A dropped event socket does not cancel the durable job and must not trigger a second socket close.

## Local API

HTTP endpoints require temporary bearer authentication except CORS preflight, and reject foreign origins and non-local hosts. Native bootstrap carries secrets in memory. WebSockets require an allowed origin and authenticate in the first JSON frame with a five-second deadline. Provider JSON-RPC messages have separate size/queue limits; API WebSocket frame-size hardening is still release work. Never place credentials in a query parameter.

Routes cover authenticated health, settings, connection diagnostics, library, resolved assets, research jobs/cancellation, normalized event replay, conversations, immutable bundles, term lookup/generation, saved reports and personal exports. HTTP errors omit raw provider output and credentials. Generation is gated by global cloud consent, which can cancel active work when revoked.

Persisted settings are not all operational features. Cloud permission, selected provider/model, explanation language and conversation expiry affect current behavior. Manual source review keeps incoming sources as unverified candidates; there is no admission-review UI yet. Update mode, start-at-login and the document-cache size are stored preferences awaiting their respective services. Connections exposes bounded subscription model discovery and explicit selection; a stored selection does not qualify live model access.

## Import parser boundary

`import_documents` extracts untrusted PDF/CSV/XLSX/HTML content only; production use goes through `import_worker`. Input is at most 5 MiB, ZIP expansion 20 MiB with 4 MiB per entry/stream, 100 PDF pages, 20 sheets, 2,000 rows, 100 columns, 10,000 cells and 200,000 content characters. Workers have a 20-second deadline and 512 MiB memory ceiling (Windows committed-memory Job Object; POSIX development resource limits). An optional Job Object memory parameter leaves provider defaults unchanged. Cancellation closes the owned process tree.

Workers receive base64 bytes and a format over stdin, no document path or provider/database credential. They return strict JSON with original hash/page/cell locators, literal values and limitations. XLSX numeric XML text is retained without float rounding; cached formula results never establish computed facts. XML preflight rejects DTDs/entities, ZIP expansion, active content and external relationships. PDF script/actions/attachments and encrypted or text-unavailable documents fail explicitly; no external decoder is enabled. Parser errors/logs never reach user output. The frozen sidecar has a narrow `--parse-import` entry distinct from database startup. Authenticated `/api/imports/preview/file` and `/api/imports/preview/url` return ephemeral typed previews with no database writes. File input streams at most 5 MiB within 20 seconds; URL JSON is bounded to 4 KiB. URL retrieval requires cloud consent, registered full-text rights and public HTTPS/DNS/address validation without redirects; unknown rights return link metadata only. Parsing shares the two-slot retrieval bound and a maximum of 20 active/queued preview operations. Disconnect, cancellation and service shutdown close owned parsing; cloud revocation cancels online previews only. The Sources screen escapes text and paginates references, distinguishing checked/retrieved time from unknown publication dates. Native file selection through the compiled WebView2 input and packaged parsers passed isolated acceptance. Durable attachment restore and explicit retained-source learning are described below.

Retained imports use immutable `import` records in the existing database document table, with strict provenance, parser fingerprint/locators, explicit storage/backup permission and base64 bytes. They are never `asset`/`bundle` records or financial inputs. The storage boundary enforces 5 MiB per input, 100 documents and 64 MiB aggregate bytes; PostgreSQL serializes capacity admission with record writers. Format-2 backups separate raw bytes into UUID-derived members and validate an exact manifest/reference/checksum mapping before atomic restore. Format-1 libraries remain compatible. Archive reading never parses documents or extracts files. Separate authenticated retain routes require explicit storage permission, reparse the submitted/freshly retrieved bytes and match the displayed preview fingerprint before writing. Metadata listing excludes raw bytes; opening a document reparses its original bytes under the bounded worker queue and rechecks current rights without retrieval or provider calls. GET bodies are consumed before disconnect monitoring. Sources exposes retention and original-source navigation; Connections shows archive attachment counts/bytes. Aborted save responses cannot promise that no write occurred, so the UI refreshes the list and asks the user to check before retrying. Separate provider transmission and interpretation controls are described below. See DEC-030 and [migration](docs/MIGRATION.md).

## Retained document explanations

Retained-document learning is a separate interpretation service (DEC-031), never factual context. Sources looks up an existing explanation without inference; a new request requires cloud consent and exact per-document transmission permission. It reparses original bytes/current rights and sends at most 300,000 serialized context characters to the selected provider with `allow_browsing=False`. One inference slot, the shared 20-job bound, owned runtime cancellation and a 180-second operation limit apply. Unexpected tools/reviews, overlong output, invalid references, unsupported numeral tokens and known advice fail without publication. Short literal quotes bind to original page/cell locators; this establishes provenance rather than semantic truth. Publication stores one immutable `import_explanation` record and completed job in the same transaction. Read-only lookups and completed-job reads revalidate the original document, preserving offline access, original dates and separate generated dates. Cache keys include document ID/hash, language and level; provider switches do not replay inference or discard a valid cached interpretation. Archives preserve explanation/document/job references; older binaries remain unqualified rollback targets. No provider diagnostics, full prompts or raw file bytes are stored in explanation jobs.

## Term explanations

Conversation research hydrates up to five distinct immutable assistant bundles from the last twenty messages after the latest scope change. Full identity fingerprints must match. A 400,000-character budget admits complete contexts, never detached claims without their sources. Context includes original bundle/date metadata and version-specific hashed source aliases; notes are excluded and current registered rights are checked. The application resolves reused aliases to stored URLs even when the model omits or substitutes source objects. New publication retrieves and validates support again, preserving original snapshots and dates. This uses existing JSON documents, not a new citation database or SQL migration. Publication and archive restore share claim/source-reference validation.

TermRequest, TermResult and TermExplanation define version-scoped learning interpretations. A normalized term, bundle ID, language and reader level identify a cached explanation; switching providers can reuse it. Hover/focus performs read-only lookup. Click, selection confirmation or form submission can enqueue generation with cloud permission. The retained curated glossary supplies clearly labelled English definitions offline.

Term jobs share research cancellation, durable status, the inference semaphore and the bounded queue. Codex browsing is disabled in process configuration for these jobs; unexpected tool activity fails closed. Only admitted facts and their sources enter the prompt. Snapshot interpretations require source IDs from that context, while generic definitions explicitly have no source citation. Copied numeral tokens and known advice patterns are checked conservatively. These checks do not prove semantic entailment, translation quality or comprehensive advice detection: explanations remain labelled interpretations and never feed facts, charts, calculations or later factual evidence.

Publication commits the explanation and completed job together without changing the asset snapshot. Refresh queues previously used terms against the new bundle, preserving earlier explanations; overflow is reported and deferred until requested. Portable backup validation checks explanation identity, version references and citations, including completed term jobs. Citation routes carry both bundle and source IDs so history navigation preserves the cited version. No new glossary dependency is needed.

## Research admission

Resolve identity before storing canonical output. Research calls an application-owned identity resolver before inference and rechecks unresolved provider proposals against that resolver after generation. Multiple independent matches produce disambiguation without inference. Complete identity hashes bind name, symbol, listing, type, currency and identifiers; even the same ID cannot change those attributes. The SEC adapter retrieves the public listing map with a configured contact, bounded parsing, an hourly in-memory cache and a failed-request cooldown. IDs include CIK, exchange and ticker; missing exchange is unresolved. Type/currency remain unknown because that source does not establish them.

OpenFIGI v3 provides a second independent namespace through anonymous mapping/search. Exact FIGIs, tickers and full names can resolve; check digits, bounded metadata and duplicate detection precede publication. General queries preserve SEC and FIGI choices separately; qualified IDs route to one registry. Name/symbol resemblance never creates a CIK or merges identities. Missing metadata, partial pages, source failures and more than twenty choices stop inference and expose at most twenty verified choices for explicit selection. Only reviewed type combinations classify instruments; ETP does not establish ETF and generic contracts remain unknown. Currency/trading status remain unconfirmed. Cache holds at most 256 requests for one hour; process-shared request starts are separated by three seconds for mapping and fifteen for search, without waiting/retry. Broader live category qualification, issuer/instrument associations, financial retrieval and gap filling remain M2 work.

`backend/app/source_registry.py` now owns explicit document path rules, publisher/credibility, permissions, review dates/references and freshness bounds. Initial SEC listing/submission metadata and bounded filing-text paths are registered; arbitrary SEC and Investor.gov paths no longer inherit domain-wide permission. Unknown rights are link-only. Public-address pinning, TLS host verification, no redirects and a 2 MB response bound remain mandatory. All SEC requests require a locally configured contact and share a five-request-starts/second limit. Filing text additionally requires the independent issuer CIK in its path and full-name textual support. Candidate verification, rights, dates, excerpts and hashes are never trusted, including manual-review and retrieval-failure paths.

The two OpenFIGI lookup endpoints are registered for metadata only. Their JSON request bodies are limited to 4 KB and cannot change the destination, add authentication or enable arbitrary POST requests. The generic text verifier cannot treat this metadata permission as full-text claim support. No additional runtime dependency is needed. Identity fingerprints support consistency, not completeness or accuracy guarantees from the registry.

Only literal supported prose without a structured numeric value can enter facts; unknown instrument type suppresses type-dependent sections. Unsupported numeric/calculation candidates from permitted documents remain nonnumeric notes. Claims/notes citing missing, rejected, link-only, metadata-only or summary-only support cannot smuggle raw/derived restricted text into the library. Summary permission requires a separately validated summary path before admission. Weekly and Earlier context admission remain disabled pending independent dates/selection. Broader source rights, numeric/unit/period admission, semantic support, restatements/conflicts and calculations remain required before release.

Optional source review uses a separate memory-only broker, not runtime permission approvals. Identity lookup prepares exact registered issuer URLs before financial retrieval. Users explicitly select source subsets, skip or cancel; all identity, support and usage gates still apply. Pending requests expire after 120 seconds, hold no inference/retrieval slots, and never survive restore/restart. A per-run scope remembers decisions only for exact URLs under unchanged registered rules, including source aliases, and keeps review active after a settings toggle. No raw provider titles, excerpts, diagnostics or credentials are exposed by review DTOs. See DEC-033.

Do not store arbitrary raw provider output. Research streams safe progress and publishes up to three immutable admitted section checkpoints before its final bundle: structured financial history, opted-in private market history and the first independently supported narrative section. A checkpoint passes existing identity/support/rights/numeric gates and contains no candidate sources or notes. Bundle/job/event publication is atomic; only the completed version advances the asset/conversation. Cancellation/failure/restore retain checked sections with an explicit incomplete marker and original source routes. Manual review blocks subsequent automatic admission, preserving earlier immutable evidence. See DEC-032/042. Exclude notes from canonical evidence context and charts. Personal Markdown/JSON exports retain completion/source dates and omit source excerpts by default. Full-library backups preserve permitted evidence needed for restoration.

Typed cache lookup uses normalized exact symbol/name/identity matching, with qualified identities taking precedence. Ambiguous cached symbols return candidates without inference. Fresh online reuse requires exact identity/language/reader level, an independent identity recheck, permitted registered sources and recent underlying publication/as-of dates as well as retrieval/bundle dates. Missing dates, future dates, old evidence, legacy missing proof/level and latest-information requests cause rechecking. Adapter-specific coverage for latest data remains open; recent retrieval alone is never enough. Offline keeps saved evidence without retrieval or calculation and refuses a known language/level mismatch. Opening saved versions remains read-only. New bundles store reader level and identity proof; old versions retain null/unknown defaults. Substring matching never selects an identity.

## Structured financial observations

Private market evidence uses an optional typed `market` object and `market_adapter` sources, separate from SEC issuer observations. Admission consumes a bounded parsed candidate plus independent OpenFIGI concordance and an explicit boolean personal-mode opt-in. Revalidate exact decimal strings, ordered unique dates/actions, OHLC relationships, previous-day cutoff, compatible listing/adjustments, fixed source metadata and original fingerprints. A normalized-record checksum detects accidental mutation; it is not an authenticity signature. Restore evaluates consistency at the original checkpoint, never refreshes source dates or contacts providers.

`market_returns` generates source-linked saved results using DEC-041: identical observed endpoints, separate close/adjusted-close ratios, exact rational arithmetic and final six-place rounding. Missing baseline/rows, sparse history or one point yields a typed reason with no value. Admission/restore recompute only to check stored results; pre-calculation versions remain without results. `return_method` identifies the method, which is never treated as reported fact or mixed with SEC share-based valuation inputs. DEC-046 includes this typed market object in consented numerical AI context; shareable exports remain filtered.

DEC-045 adds optional `MarketValuations` inside the private market object with its own original statistics Source. The pinned worker makes a separate exact fundamentals-timeseries request, bounded to reviewed metric/frequency types and dates. Capture original JSON before dataframe coercion; parse Decimal, preserve per-observation dates/period labels and nullable currency, and withhold monetary values without currency. Independent listing mapping remains required through the associated market evidence. Source selection, consent and cancellation are rechecked around its shared retrieval slot and publication. A valuation failure preserves prices with an explicit gap. Section-checkpoint admission recognizes both typed numeric sources while keeping arbitrary metadata sources forbidden. Fingerprints include new data but omit absent optional fields for older snapshots. Shared factual context includes the typed numerical object and both original citations under DEC-046; shareable exports still omit them. No generated interpretation becomes numerical evidence or app-calculated P/E. UI controls select retained observations with original-version citation navigation and contextual term learning.

`MarketHistory` presents admitted saved bars, date-relative chart windows, original exact decimals/actions and stored method results. BigInt differences map prices to bounded display coordinates without rounding source values; sparse/known missing history never gains imputed points. Original source routes retain bundle IDs. Admitted numerical panels support term selection. Raw source metadata, unsupported prose and uncertain notes retain selection guards; they do not enter factual context. Connections exposes the strict default-off preference; opt-out cancels running research but does not erase historical evidence. No new return is generated on opening/filtering an offline snapshot.

`source_operations` removes Yahoo evidence and transitive claim dependencies from shareable exports. DEC-046 separately admits validated typed numerical evidence into the common cloud context; unsupported Yahoo prose remains excluded. Unattributed notes are omitted from private-containing exports. A fixed export notice explains the omission; SEC observations and their original references remain available. URL recognition also restricts legacy Yahoo references. Term validation uses admitted factual context and copied numbers from the cited observations. Generated interpretations never become factual context. Same-user backups retain typed private history and reset `experimental_yahoo_enabled` along with cloud/start-at-login settings.

`market_research` adds default-off source-mode orchestration after issuer observations and before inference. Exact private numerical review rules are separate from general text rules. Review holds no queue slots; retrieval uses the shared two-slot limit and cancellation ownership. Recheck opt-in/review after waits and before publication. EODHD account scope must match the observed free tier (20 calls/day, zero extra allowance, room for the account/history requests); otherwise stop without Yahoo retry. A missing key or insufficient entitled history can use the user-selected bounded Yahoo worker. The five-year request includes seven days of baseline buffer. Only independently mapped Yahoo candidates are admitted in this slice; the EODHD candidate remains separate. Under DEC-046, models receive validated numerical observations and original citations through the shared context, while immutable checkpoints/final versions retain values and references. Retrieval remains default off; common cloud consent governs explanations. DEC-043 adds a same-executable frozen market worker with scoped qualification tracked separately.

DEC-035 clarifies intended API-first dashboard orchestration: assess the requested fields against fresh permitted cache and configured structured sources, and let the selected agent investigate only relevant remaining gaps. The current research service already supplies SEC observations/filings before generation, but a general sufficiency planner and additional market/news adapters are not implemented by this clarification. Dashboard learning should inherit bounded original evidence/version references. Permission for local display must be kept distinct from persistence/archive and cloud-model use when adding other sources.

The developer helper `scripts.configure_data_sources` now stores allowlisted market/news credentials through `backend/app/data_credentials.py` in the explicit Windows vault backend, with hidden interactive input, bounded validation and readback. It never reads arbitrary environment files, copies WSL/agent credentials or calls providers. Vault records have no database/frontend/archive representation; a status check discloses presence only. Saved plan labels do not qualify entitlement, and no market adapter is automatically activated. No SQL or archive revision changes. Future packaged Connections onboarding and credential-backed retrieval require their own checks.

`backend/app/sec_financials.py` parses bounded official US-GAAP concept responses without binary-float conversion. It preserves original units, period dates, accession/form, reported fiscal labels and source fingerprints. Similar concepts/currencies stay separate. Latest filed values supersede older records without discarding them; same-date conflicts remain unresolved. Duration lengths distinguish annual/quarter/YTD or nonstandard periods; missing quarters are never filled with older years or invented Q4 values. Limits cover response size, rows, decimal expansion, nesting and revision count.

`backend/app/structured_financials.py` obtains separate FIGI instrument and SEC issuer records. The initial common-stock association requires exact normalized full-name/symbol equality, one SEC match and a reviewed NYSE/Nasdaq venue correspondence; composites and near names remain unconfirmed. It preserves both proofs and never inserts the CIK into instrument identity. It retrieves nine registered concepts with shared SEC fair-access limits, partial availability and cancellation. Access/rate/server errors stop further requests. Unsupported units/forms and missing history/prices/corporate actions remain explicit. No extra dependency is used.

`financial_evidence.py` attaches adapter observations to the optional typed `EvidenceBundle.financials` document. Exact decimal strings remain separate from provider Claim.value. The bundle validator checks separate issuer/instrument proofs at the historical association checkpoint, registered source rights/hash/date references, concept/unit/period fingerprints and recomputed revision states. One concept snapshot uses one retrieval. Bounds include 40,000 rows, 128 revisions per period and nine concept sources. It rejects changed scope or internally inconsistent restored records before any publication/restore writes; these checks do not authenticate an externally modified archive.

Only current unconflicted observations enter numeric factual context, with units, dates and citations. Exports retain all versions and availability gaps. Legacy missing financial documents stay unknown. Normalized records survive actual PostgreSQL restore/restart without a SQL or archive version change.

`financial_ratios.py` retains application-owned same-filing net-income/revenue percentages under `financials.ratio_method` and `ratios` (DEC-044). Each result records exact observation and source IDs, reporting interval, revenue concept and either rounded percentage or missing reason. Publication/restore recompute the method to validate stored results, without generating results for older snapshots. Cloud reuse aliases original source IDs per evidence version; UI and exports separate calculations from reported observations. These issuer-only calculations do not establish historical P/E share-basis compatibility.

The financial view groups admitted observations by exact concept, unit and period type, retaining original decimal strings. Fixed-scale BigInt arithmetic produces only bounded chart coordinates; source values never round-trip through JavaScript floating point. Current conflicts/superseded records cannot supply chart points. Defaults show five annual periods or twelve quarters; all retained filing versions remain available in paginated detail with filing dates/accessions and immutable bundle/source links. Share-based and nonstandard-duration trends stay unavailable without compatible adjustments/periods. Price, total-return and historical valuation calculations are not implemented by this issuer-history view and remain explicit gaps. Asset sections reuse stock/fund headings without importing fixture data; unknown asset types suppress type-dependent sections.

ResearchService now retrieves applicable financial observations after identity resolution and before acquiring the shared inference slot. Separate retrieval workers own the two retrieval slots until blocking I/O actually finishes, even if their caller is cancelled. Cancellation signals prevent follow-up financial requests; close waits for owned workers. The single inference semaphore is shared with term explanations. Consent is checked before/after retrieval, before inference and before atomic publication. Manual source review prevents automatic financial retrieval/publication, including a change during inference. Adapter failures produce fixed availability notes, never model numeric fallback.

Application-owned financial citations cannot be overwritten by model copies. Current observations and explicit gaps are passed as separately labeled historical issuer context and persist in the final immutable snapshot. Original dates remain intact. Financial cache reuse remains disabled; fresh structured retrieval runs on each online request.

`sec_filings.py` retrieves one permitted submissions index for the independently verified issuer, checks exact CIK/name, correlated columns, dates, reviewed forms and canonical document paths, and offers up to twenty filing-event candidates to gap research. It retains a bounded in-memory index for that request only. Unsupported forms do not become events. At most two newest candidate pages are independently read before inference and validated with the issuer proof. Their exact source text is untrusted context for candidate quotations; model copies cannot overwrite these application-owned citations. Alias IDs reuse verified pages and failed prefetched page requests are not retried. Source claims still require literal support. Exact candidate URLs may use the separate issuer for path ownership, then return to the confirmed instrument scope. `Source.filing_publication` binds the filed/report dates to the index URL/fingerprint/retrieval time and accession/document; candidate metadata always clears model proofs. Bundle/publication/restore checks validate these references together with the issuer proof.

Page support and date support remain separate. Original dates appear in the existing source drawer and exports; a recently fetched old document does not establish current news or real-time prices. Missing current filing coverage and absence of today's independently dated sources produce explicit notes. Filing events are partial news coverage. The production-path live helper uses the normal qualified Codex runtime and records fixed completed web-action types from the installed protocol, requiring search/open/follow-up plus independent dated claim support and structured observations. At least one admitted dated quote must match returned text in the completed page-open result for the same URL; those result strings are bounded and discarded with the run. It never stores raw queries/transcripts/contact or changes qualification policy. Current live outcomes and remaining M2 review belong in STATUS and dated evidence.

## Runtime integration

The explicit inventory helper measures complete installed-binary request serialization through a credential-free local transport after closing the authenticated metadata process. It retains only tool names and declaration hashes. Pinned serializer/contributor review, identical selected-model catalog/tool policy and matching provider capabilities are required to relate this measurement to separate subscription live evidence. This developer check cannot promote runtime capabilities or certify other binaries/models/platforms. See [DEC-021](DECISIONS.md#dec-021-measure-the-installed-tool-declaration-without-account-traffic). Cloud skill discovery and agent message-board tools are explicitly disabled and validated with the remaining tool policy.

AIRuntime exposes discovery/check and normalized async streaming with per-operation browsing policy. Codex creates an ephemeral App Server thread per operation and requires provider-managed ChatGPT authentication; app-owned history is context rather than a resumed provider thread. Gemini execution and the experimental restricted Claude transport remain unqualified. RuntimeCapabilities separates unqualified/protocol_only/live from authentication and preserves exact prerelease/build identity. Version detection alone remains protocol_only for Codex 0.158.0-alpha.2.1; native Windows executable SHA-256 verification and authentication enable its reviewed capabilities. Each production turn additionally verifies the measured gpt-6-astra model/catalog, policy digest and typed provider capabilities before inference. Any drift stops without fallback. This scope is code-owned and never populated by settings or model output; see [DEC-022](DECISIONS.md#dec-022-bind-live-qualification-to-the-measured-runtime-scope). Streaming exposes normalized progress and completed answers, never raw reasoning. Runtime qualification is separate from pipeline/native/public release acceptance.

Provider subprocesses receive only allowlisted process environment variables, with no inherited API keys or database credentials. Codex uses an app-private CODEX_HOME and a separate provider-managed sign-in. The Connections screen initiates App Server's chatgptDeviceCode flow, displays only its allowlisted official verification URL and temporary code, polls normalized in-memory state and supports cancellation. The app accepts provider-managed ChatGPT accounts only; it does not import external tokens or API keys. Codex owns token persistence and refresh outside the library. Device codes expire after ten minutes and are cleared on every terminal outcome; sign-in responses prohibit HTTP caching. Signing in does not enable cloud research. Actual account authorization and live inference still need qualification.

The bounded JSON-RPC transport preserves notifications received before a request response, rejects unexpected server requests and caps queued messages. No raw provider diagnostics reach the UI. Claude requires subscription auth status and restricted/safe modes; older unsupported versions fail rather than dropping these protections. Avoid shell parsing on Windows; resolve npm runtime entry points explicitly and suppress helper console windows. Hidden reasoning, stderr, tools' arbitrary arguments and raw diagnostics never enter events.

During a correlated research turn, v2 command/file/permission requests can enter a memory-only access review. The policy offers denial or cancellation, never a grant: shell/file changes/broader network permissions are outside the research tool policy. The authenticated API binds each single-use review to an active job, expires it after 60 seconds and rejects foreign/replayed decisions. No vendor arguments or permission amendment crosses that API. Denial maps to decline or empty turn-scoped permissions; cancellation/expiry stops the run. Reviews disappear on consent revocation, cancellation or shutdown and never enter archives. Cached-evidence operations stop on any access request. Actual permission denial/cancellation passed for the scoped Codex qualification; shell/file tools remain unadvertised and ungranted. See [DEC-012](DECISIONS.md#dec-012-access-review-cannot-expand-research-policy).

Codex policy uses a dedicated workspace root marker and refuses custom profile/workspace/system startup configuration or file credentials, except the exact provider-persisted Windows elevated setting. Launch flags require keyring storage, strict parsing, disabled host execution/extensions/browser/desktop tools, no telemetry and no inherited instruction/skill context. Before thread creation, config/read and experimentalFeature/list must agree with the app policy; the returned thread must have one matching workspace root, no instruction sources, an OpenAI provider, user-reviewed approvals and a read-only sandbox with network access disabled. Hosted web search remains separately controlled per operation. The installed protocol uses on-request/read-only request values and returns a readOnly sandbox object. unified_exec alone cannot establish execution isolation; the pinned runtime source gates shell commands with shell_tool. See [DEC-011](DECISIONS.md#dec-011-verify-effective-codex-isolation-before-turns) and current qualification evidence in STATUS.

After selecting a subscription model, the adapter reads bounded metadata through the isolated diagnostic process, narrows only reviewed tool-bearing fields, and reopens App Server with a single-model temporary catalog. Model identity and all other metadata are preserved. Direct mode, disabled shell/patch/agent/REPL metadata, empty experimental tools and disabled tool discovery close metadata overrides of feature flags. Configuration also disables agents, plan/input/time tools and other auxiliary features. The normalized config omits plan/input settings (its tools object contains only legacy web_search=null); their exact strict sessionFlags layer is mandatory, alongside the effective agent switch. Catalog shape/identity, file identity/content, configuration, features, subscription account and selected thread model are rechecked before inference. The diagnostic command alone omits its unsupported strict flag; generation always retains strict parsing. All owned processes and catalog files are cleaned up on terminal paths, and a replaced file is preserved for review. Research exposes only intended hosted web and request_permissions under deny/cancel authority; cached operations request neither. Exact live inventory remains separate acceptance, not an inference from these settings. See [DEC-020](DECISIONS.md#dec-020-restrict-selected-model-metadata-and-expose-denial-only-requests).

Connections can request a normalized model catalog after a supported subscription account is verified. The adapter bounds pagination, filters hidden/non-text models and rejects malformed or ambiguous identifiers/defaults. Catalog rows establish neither entitlement nor live qualification. Settings stores one optional model for the selected provider; the UI clears it on provider change. New jobs snapshot that choice, reject foreign provider/model requests, and re-read the catalog before starting a thread. An absent explicit model or server-side model substitution fails without fallback. A null choice explicitly requests the catalog's current default. Settings changes are serialized and provider/model changes recheck active work after discovery; consent revocation still cancels work. Gemini/Claude catalogs remain unavailable until their adapters are qualified.

Before release, pin tested version ranges, validate capability negotiation, ensure provider configuration/hooks/MCP cannot expand permissions, implement complete sessions/reconnect/approvals and qualify subscription accounting. No untested adapter is a completed integration.

Source-runtime lifecycle now uses suspended Windows launch, verified Job Object assignment and kill-on-close descendants, including when a launcher exits before its children. Startup ownership failure prevents execution. Provider checks/auth/streams share this launcher. Closing streams on validation failure and a bounded turn/interrupt on cancellation precede process cleanup. Message/item/completion events require the active thread/turn; JSON-RPC response IDs use exact integer types. Pending reviews stop on leader exit. Recovery keeps interrupted jobs and never retries inference; explicit new requests use fresh ephemeral provider threads. Codex answer assembly also tracks bounded message-item lifecycles. Pending command/file declarations are tracked separately so the following correlated access request can reach deny/cancel review. ## Packaging and lifecycle

Portable backups contain two versioned JSON documents and, for format 2, separately registered attachment members in a ZIP container: a manifest with content checksum and an allowlisted snapshot of application records, jobs and normalized events. No filesystem tree, SQL, provider profile, credential-store entry or environment variable is read. Backups use a repeatable-read PostgreSQL snapshot. Archives are bounded (128 MiB compressed, 256 MiB content in this preview), schema-checked and checked for duplicate identities, missing references, wrong-asset citations and raw events. Unknown record kinds fail instead of being silently omitted. Checksums establish integrity, not authorship.

The Connections page provides download, preview and explicit restore controls. Restore requires an empty library, binds the final action to the previewed archive fingerprint and rechecks emptiness under database table locks. Every write commits together; failure rolls back the operation. Existing research is never overwritten. Cloud research and start-at-login reset to off, and active jobs restore as interrupted. Saved versions remain distinct from current pages. This covers current database-held library content; format 2 covers bounded retained attachments; larger streamed archives and cache scale remain M9 work. Application upgrades and coordinated binary/schema rollback remain separate work.

The native host creates the session token before boot and owns the service stdin lifetime. The sidecar acquires an exclusive library lock. PrivatePostgres initializes a separate data directory with SCRAM authentication and a keychain-owned password, binds loopback on a free port and stops only its own data directory. A surviving private server can be recovered only after authenticating and verifying its actual data directory and loopback binding. Stale PID files are left for PostgreSQL to handle. Native startup has a bounded response timeout and cleans up an unsuccessful owned sidecar. The release host uses `dunce::simplified` for the PostgreSQL resource path because initdb's sibling-process lookup cannot use Tauri's ordinary verbatim Windows path. Simplification preserves ambiguous/reserved path spellings instead of stripping the prefix indiscriminately. Compilation, isolated startup and native file previews passed; full native lifecycle/tray and clean-machine acceptance remain M9/M11.

The initial migration creates local records/jobs/events. Unknown or future schemas fail closed. Later migrations require a backup restored and verified in a separate cluster. pg_restore --list only checks archive readability; it is not restore validation. A release updater must preserve newer research, stage binaries and coordinate app/schema rollback.

Build PyInstaller separately for each OS. The current script accepts Windows x64 only and copies the sidecar to Tauri's target-named binaries directory. Release Tauri configuration expects a PostgreSQL distribution under `src-tauri/resources/postgres`; this runtime is not supplied by the repository or downloaded by the script. Development uses `LTT_PG_BIN` without touching an existing database/service. PostgreSQL 17 is the locally exercised major version; automatic runtime/major-version switching is not implemented. Cargo.lock and `--locked` preserve the native dependency resolution; native resources include the original application icon and retained direct-dependency notice. Runtime redistribution, provider prerequisites, tray behavior, clean-machine installation, updates and signing remain release checks. See [migration and packaging](docs/MIGRATION.md).
